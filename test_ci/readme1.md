## 🎯 Цель исследования

Провести сравнительный анализ **MongoDB** и **PostgreSQL** на задаче хранения данных киносервиса с объемом **10 миллионов записей** и требованием **SLA ≤ 200 мс** на все операции чтения и записи.

### Типы данных для хранения:
- 👍 Лайки пользователей к фильмам
- 📝 Рецензии с вложенными структурами (текст, автор, дата, лайки, оценки)
- 🔖 Закладки пользователя с неструктурированными вложениями
- 📊 Пользовательские клики и история действий (логирование)
- 👤 Профили пользователей с гибкими настройками
- 📦 Дополнительные неструктурированные данные с JSON-подобными документами

---

## 🏆 Выбор хранилища

### ✅ Выбрано: **MongoDB**

### Обоснование выбора

Анализ предметной области показал, что **80% данных являются неструктурированными или полуструктурированными**:

| Тип данных | Характер | Подходящая БД |
|------------|----------|---------------|
| Профили пользователей | Гибкая схема, единый документ | 🟢 MongoDB |
| Закладки | Неструктурированные вложения | 🟢 MongoDB |
| Логи кликов | Append-only, высокая интенсивность записи | 🟢 MongoDB |
| Рецензии | Полуструктурированные с вложениями | 🟢 MongoDB |
| Лайки | Простые связи | 🟡 Обе подходят |

### Почему не PostgreSQL?

PostgreSQL — великолепная реляционная СУБД, но для данной задачи это «сопротивление материала»:
- ⚠️ Использование `jsonb` усложняет индексацию и замедляет чтение глубоких вложенностей
- ⚠️ Сложные запросы с `jsonb`-операторами (`->`, `->>`, `@>`)
- ⚠️ Необходимость миграций при изменении структуры профилей
- ⚠️ Оверхед на транзакции для задач, не требующих строгой консистентности

> 💡 **Примечание:** В enterprise-архитектуре часто используют гибрид (Polyglot Persistence): PostgreSQL для биллинга, MongoDB для профилей, логов и контента.

## 📊 Модель данных

### Коллекции MongoDB

```javascript
// 1. Пользователи с профилями и закладками
{
  "_id": 1,
  "profile": {
    "theme": "dark",
    "settings": { "nested": { "val": 42 } }
  },
  "bookmarks": [
    { "movie_id": 123, "meta": { "note": "..." } }
  ]
}

// 2. Фильмы с преагрегированной статистикой
{
  "_id": 1,
  "title": "Movie 1",
  "avg_rating": 4.5,        // Обновляется атомарно
  "total_likes": 1500       // Обновляется атомарно
}

// 3. Рецензии
{
  "_id": 1,
  "movie_id": 1,
  "user_id": 42,
  "text": "...",
  "date": ISODate("2026-08-27T10:00:00Z"),
  "likes_count": 15,
  "dislikes_count": 2
}

// 4. Лайки пользователей
{
  "_id": 1,
  "user_id": 42,
  "movie_id": 1,
  "type": "like"
}

// 5. Неструктурированные события (ключевой сценарий!)
{
  "_id": 1,
  "user_id": 42,
  "timestamp": ISODate("..."),
  "meta": { "event_type": "click" },
  "payload": {
    "data": { "value": 75, "label": "abc" },
    "flags": [true, false, true]
  },
  "context": {
    "level_0": {
      "level_1": {
        "level_2": { "value": "deep" }
      }
    }
  }
}
